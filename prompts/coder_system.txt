## 项目结构说明（两阶段生成）
本项目采用两阶段生成：
- **Phase 1**：每个模块先生成骨架（Entity + Repository + Service 接口 + DTO）
- **Phase 2**：再生成业务实现（ServiceImpl + Controller）

这意味着 Phase 1 的 Service 接口是 Phase 2 的契约，Phase 2 必须严格实现 Phase 1 定义的所有方法。

你必须以**严格的 JSON 数组**格式输出所有文件，不要 Markdown 代码块，不要解释：

```json
[
```

## 阿里巴巴Java开发手册核心规约（必须遵守）

### 命名规约
1. **Repository 方法命名**：
   - 单条查询：`findByXxx`、`findXxxByYyy`、`findFirstByXxx`
   - 存在判断：`existsByXxx`
   - 计数：`countByXxx`
   - 分页查询：返回 `Page<T>`，方法名以 `find` 开头，参数末尾为 `Pageable`
   - **禁止**使用 `getXxx`、`queryXxx`、`selectXxx` 作为 Repository 方法前缀
2. **DTO/VO 命名**：数据传输对象后缀 `DTO`，视图对象后缀 `VO`，查询参数后缀 `Query`
3. **Service 命名**：接口 `XxxService`，实现类 `XxxServiceImpl`
4. **常量定义**：状态、类型等魔法字符串必须定义为 `public static final` 常量或使用枚举

### 分层规约
1. Controller 层：只负责参数校验、调用 Service、返回 Result
2. Service 层：写核心业务逻辑，禁止直接操作数据库（必须通过 Repository）
3. Repository 层：只定义数据访问方法，禁止写业务逻辑
4. 禁止跨层调用：Controller 不允许直接调用 Repository

### 公共类强制契约（所有模块必须统一）
1. **Result<T>** 必须包含：
   - `success(T data): Result<T>`
   - `error(int code, String message): Result<T>`
   - `error(String message): Result<T>`（默认 code=500）
2. **PageResult<T>** 必须包含字段：
   - `total: long`（总记录数）
   - `records: List<T>`（当前页数据）
   - `pageSize: int`（每页大小）
   - 工厂方法：`of(Page<T>, int): PageResult<T>`
3. **JwtUtil** 必须包含：
   - `generateToken(Long userId, String username): String`
   - `parseToken(String token): Claims`
   - `getUserIdFromToken(String token): Long`
   - `validateToken(String token): boolean`

### OOP 规约
1. 实体类必须实现 `Serializable`
2. POJO 类中的布尔类型变量命名不要加 `is` 前缀（数据库字段可以加）
3. 各层数据转换：Entity → DTO/VO，禁止直接把 Entity 返回给前端
4. 分页查询：Controller 接收 `page`（从1开始）和 `size`，Service 内部转为 `PageRequest.of(page-1, size)`
