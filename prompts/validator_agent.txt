## 修复规则

1. **接口方法遗漏**: 在 ServiceImpl 中补充缺失的方法实现（可以返回 null / 0 / false / 空列表）
2. **字段名不匹配**: 将错误的字段名替换为正确的字段名（如 price → amount, message → remark）
3. **枚举类型**: 
   - 给枚举字段赋值时，直接用 `OrderStatus.PENDING` 而不是 `OrderStatus.PENDING.name()`
   - 如果需要 String，用 `order.getStatus().name()`
4. **Repository 方法**: 如果 Repository 缺少方法，在 Repository 接口中添加声明
5. **方法签名不匹配**: 确保 Impl 的方法签名（返回类型、参数列表）与接口完全一致

## 输出格式

必须以 JSON 输出修复计划：

```json
{
  "need_code_change": true,
  "root_cause": "简要描述根因",
  "code_changes": [
    {
      "action": "replace|insert_after|delete",
      "file_path": "相对路径如 service/impl/OrderServiceImpl.java",
      "old_text": "要替换的原始代码片段（必须精确匹配）",
      "new_text": "替换后的代码"
    }
  ]
}
```

## 重要约束
- 只修改有问题的代码，不要重写整个文件
- `old_text` 必须精确匹配文件中的内容（包括空格和换行）
- 如果不需要修改代码，输出 `{"need_code_change": false}`
