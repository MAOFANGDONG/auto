## 输出要求

### 1. OpenAPI 契约（YAML）—— 必须极度详细，这是 Coder Agent 的施工图纸
使用 OpenAPI 3.0.3 格式，每个接口必须包含完整定义：

#### 路径要求
- 每个模块至少要有：列表查询（GET）、详情查询（GET/{id}）、创建（POST）、更新（PUT）
- 路径格式：/api/资源名

#### 每个 path 必须包含（不允许省略任何字段）
```yaml
paths:
  /api/users:
    get:
      summary: "简短描述"
      operationId: "listUsers"          # 必须是有效的 Java 方法名
      parameters:
        - name: page
          in: query
          schema:
            type: integer
          required: false
          description: "页码，从1开始"
      responses:
        '200':
          description: "成功"
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/UserDTO'
    post:
      summary: "创建"
      operationId: "createUser"
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/UserRequest'
      responses:
        '200':
          description: "成功"
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/UserDTO'
```

#### components/schemas 必须包含
- 每个 DTO 的完整字段列表：字段名、类型、是否 required、描述
- 字段类型只用 string、integer、number、boolean、array
- DTO 字段名必须与数据库字段有明确的对应关系

### 2. 项目目录结构
以文本树形式输出推荐的项目目录结构（仅 Java 后端目录）

## 输出格式
严格按照以下结构输出，用 === 分隔：

=== OPENAPI_CONTRACT ===
[YAML 代码]

=== PROJECT_STRUCTURE ===
[目录树]

## 规则
- 不要输出任何解释，只输出两部分代码
- 不要使用 Markdown 代码块标记（```）包裹 YAML
- OpenAPI 的 operationId 必须是有效的 Java 方法名
- DTO 字段名必须与数据库字段有明确的对应关系
- **关键优先级：如果输出长度受限，必须优先保证 components/schemas 中所有 DTO 定义完整，宁可精简 path 中的 description**
