## 重要提示
1. **多文件联合修复**：如果错误涉及多个文件（如 Controller 调用 Service 不存在的方法），请同时在所有相关文件中给出修复操作
2. **先修根因再修症状**：优先修复导致错误的根本原因（如接口缺失），再修复调用方
3. **验证一致性**：修改后确保接口定义和调用方保持一致

## SWE-agent 原则（必须遵循）
1. **Reason first**：先分析错误根因，再给出修复方案
2. **最小修改**：只修改导致错误的行，不要重写整个文件
3. **结构化的修复指令**：以 JSON 格式输出，包含具体的文件修改操作

## 输出格式
以 JSON 格式输出，不要任何解释：

```json
{
  "error_type": "dependency_missing" | "syntax_error" | "type_mismatch" | "symbol_not_found" | "config_error" | "unknown",
  "root_cause": "错误根因的简短描述",
  "affected_files": ["受影响文件路径"],
  "fix_strategy": "修复策略描述",
  "need_code_change": true | false,
  "code_changes": [
    {
      "file_path": "文件路径",
      "action": "add" | "modify" | "delete" | "replace_import",
      "old_text": "需要替换的旧文本（modify/replace_import 时必填）",
      "new_text": "替换后的新文本"
    }
  ]
}
```

## 常见错误类型处理
- **dependency_missing**：缺少依赖，fix_commands 中给出安装命令
- **syntax_error**：语法错误（如文件截断、括号不匹配），need_code_change=true
- **type_mismatch**：类型不匹配（如 String 传给 Integer），给出转换建议
- **symbol_not_found**：找不到符号（如缺少 import、方法不存在、Lombok 没生成），need_code_change=true
- **config_error**：配置文件错误（如数据库连接串、端口号），给出正确配置
- **package_mismatch**：package 声明与文件路径不匹配，need_code_change=true

## 修复优先级
1. 包名/Import 错误（影响编译的最根本原因）
2. 语法错误（文件截断、未闭合）
3. 类型不匹配
4. 符号未定义
