## 输出要求

### 1. 数据库 Schema（SQL）
使用标准 SQL 语法，包含：
- CREATE TABLE 语句
- 主键、外键、索引
- 注释（COMMENT）
- 字段命名用下划线（snake_case）
- 每个表必须有 created_at 和 updated_at 字段
- 用户表必须包含密码字段（建议命名 password_hash 或 password）
- **必须覆盖所有核心实体**，每个实体至少对应一张表
- 表之间必须有合理的外键关系

### 2. OpenAPI 契约（YAML）—— 这是 Coder Agent 的施工图纸，必须极度详细
使用 OpenAPI 3.0 格式，**每个接口必须包含完整定义**：

#### 路径要求
- 每个模块至少要有：列表查询（GET）、详情查询（GET/{id}）、创建（POST）、更新（PUT/PATCH）、删除（DELETE）
- 如果有分页查询，参数必须是 `page`（从1开始）和 `size`
- 路径格式：/api/模块名/资源名

#### 每个 path 必须包含（不允许省略任何字段）
```yaml
paths:
  /api/users:
    get:
      summary: "简短描述"
      operationId: "listUsers"          # Coder 会据此生成 Service 方法名，必须是有效的 Java 方法名
      parameters:                      # 查询参数必须写完整
        - name: page
          in: query
          schema:
            type: integer
          required: false
          description: "页码，从1开始"
      responses:
        '200':
          description: "成功"
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/PageResultUserDTO'
    post:
      summary: "创建"
      operationId: "createUser"
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/UserRequest'
      responses:
        '200':
          description: "成功"
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/ResultUserDTO'
```

#### components/schemas 必须包含（不允许省略）
- **每个 DTO 的完整字段列表**：字段名、类型、是否 required、描述
- **Result 统一响应**：`{ code: integer, message: string, data: 对应DTO }`
- **PageResult 分页响应**：`{ total: integer, records: [对应DTO数组], pageSize: integer, page: integer }`
- **字段类型**：只用 `string`、`integer`、`number`、`boolean`、`array`、`object`
