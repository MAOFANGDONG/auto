Agent 详情面板 点击卡片查看交互
PM
PM Agent
项目经理 / 需求解析
从中文开题报告中提取结构化需求：项目名、模块列表、实体、角色、约束、复杂度评估。
输入: report_text | 输出: JSON (project_name, modules...)
AR
Architect Agent
架构师 / 设计数据库与 API
基于需求设计数据库 Schema（SQL）、OpenAPI 契约（YAML）、推荐目录结构。使用原生 OpenAI API。
输入: modules, requirements | 输出: db_schema, api_contract
CD
Coder Agent
代码生成器 / 核心引擎
串行生成所有模块代码。关键改进：契约注入——从已生成模块提取 API 签名注入后续 prompt。
输入: modules, db_schema, api_contract | 输出: code_files[]
BD
Builder Agent
构建验证器 / 编译检查
优先使用 mvnw 编译项目，超时 600 秒。支持 Java（Maven）和 Python（pip）两种构建方式。
输入: project_name, tech_stack | 输出: build_result (success, stderr)
FX
Fix Agent
编译错误修复器
基于 SWE-agent ReAct 循环分析编译日志并修复。支持 add/modify/delete/replace_import 操作。最多 3 次。
输入: build_result (stdout, stderr) | 输出: changes[]

2. 加载 pm_agent.txt prompt 模板
3. 调用 LLM 解析
4. _extract_json(): 3层fallback提取JSON

   - 提取 ```json 代码块

💡 原理：每生成一个模块后，自动提取该模块的 Repository 方法签名和 Entity 字段，注入到后续模块的 prompt。LLM 看到的是"真实的 API"而非"猜测的 API"。

🛡️ 防膨胀：契约摘要设置总长度预算 2500 字符，按优先级排序 Repository > common > entity > dto > util。

关键设计决策

串行生成而非并行

最初使用 ThreadPoolExecutor(max_workers=3) 并行生成，但 DeepSeek API 有并发限制导致全部挂起。改为串行后稳定性大幅提升。

Lombok 后处理而非禁用

模板保留 Lombok 依赖，生成后用 lombok_remover.py 转为显式代码。LLM 生成时可用简洁的 @Data，同时兼容旧版 Maven。

Maven Wrapper 优先

Builder Agent 优先使用项目自带的 mvnw，避免系统 Maven 3.6.3 与 JDK 21 的兼容性 bug。

Architect 绕过 LangChain

直接使用 openai 库调用 API，绕过 LangChain 在 Python 3.14 下的 Pydantic V1 兼容性警告和潜在阻塞。

自动确认节点

human_review 节点目前自动 approve，用于后台批量测试。生产环境可改为真正的人工确认。

H2 内存数据库默认

模板默认使用 H2 内存库而非 MySQL，降低本地运行门槛。部署时切换为 MySQL 配置即可。
